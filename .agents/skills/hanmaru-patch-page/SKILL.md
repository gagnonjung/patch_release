# 한마루 한글패치 상세 페이지 제작 스킬

## 자동 적용 트리거
사용자가 "패치 페이지 만들어", "패치 페이지 작업해", "한글패치 페이지 올려", "패치 배포 사이트에 등록해", "패치 업로드", "홈페이지 패치 상세 페이지 수정해", "새 게임 추가해" 등 게임별 배포 상세 페이지를 만들거나 바꾸라고 할 때 **매번 우선 적용**한다. 사이트 자체 개편을 명시적으로 요구한 경우에만 디자인 변경을 검토한다.

## 필수 참조 (우선순위 순)
1. 이 저장소의 `persona-2-innocent-sin/index.html` — **사용자가 승인한 실제 HTML/CSS 구조 원본**. 설명 문서나 예전 슬램덩크 CSS가 아니라 이 파일 자체를 복제 기준으로 사용
2. `slayers-royal/index.html` — 새턴 및 정식 배포 자료가 많은 사례. 다만 페르소나 기준과 충돌하는 낡은 코드/이중 선언을 복제하지 않음
3. `SITE_DETAIL_LAYOUT_STANDARD.md` — 상세 페이지 고정 구성·주의 사항
4. `assets/css/detail-cover.css`, `support-banner.css`, `patch-warning.css`, `patch-history.css` — 공용 자산

## 1:1 구현 규약
- 가장 먼저 기준 페이지의 `<style>`을 확인하고 **본문 폭 980px, shell/hero 크기, 글꼴, 패딩, 여백, 색상, 카드 보더, 반응형 규칙**을 동일하게 유지한다. 게임별 고유 CSS를 새로 작성하거나 옛날 `slam-dunk.css` 구조를 복원하지 않는다.
- 클래스·뼈대를 실제 HTML 단위로 재사용: `nav-inner` → `shell` → `hero-banner`/`hero-copy` + `hero-preview detail-cover` → `body` → `section`/`sep` → `grid`/`fact`, `scope`, `qa`, `hash`, `download`, `steps`, `patch-warning`, `legal`.
- 정보 순서: **게임 정보 → 게임 소개 → 한국어화 작업 범위 → 현재 검수 현황 → (필요시 접이식 업데이트) → 원본 파일 정보 → 패치 다운로드 → 패치 적용 방법 → 제작 및 검수 → 경고 → A~F 권리·책임 고지**. 플랫폼 특성상 항목이 불필요한 경우 내용만 간소화
- 모바일에서는 동일한 그리드가 한 열로 쌓인다. 데스크톱과 모바일 모두 cover는 정사각 360px 최대 프레임, padding 16px, `object-fit: contain`으로 원본 비율 보존
- **경고 문구와 A~F 고지는 페르소나 기준 페이지에서 통째로 복사**. 핵심 책임·상업 이용·재배포 조건 임의 축약 금지
- 테스트 문구는 굵은 붉은색 `.qa p.test-env`. 정적 QA PASS와 실기·에뮬레이터 런타임 미검증을 반드시 구분
- 다운로드 UI는 `.download` + `.download-link` + `.hash`. 새 게임별로 다른 버튼/헤더/스코프 카드 구현 금지
- 필요한 사실만 게임별로 치환: 타이틀·원제·플랫폼·패키지 이미지·장르·설명·실제 패치 범위·날짜·버전·디스크 트랙 수·적용법·검증된 해시·원문 링크
- 링크/해시/버전/검증 결과는 실제 릴리스 자료에서 확인된 것만 기재한다. **기존 배포 URL·해시를 바꾸거나 삭제하지 않는다.** 미확인 정보는 미확인으로 적는다
- **모든 공개 프로젝트 페이지에서 오류 제보·버그 신고·피드백 게시판으로 연결되는 링크를 넣지 않는다.** 기존 링크가 있으면 제거한다. 다운로드·후원·권리 고지 링크는 보존한다.
- **사이트에 새로 작성하는 사용자 표시 문구에는 `공개`, `배포`, `정식 공개`, `정식 배포`, `배포 완료` 등을 상태·홍보 표현으로 사용하지 않는다.** 프로젝트 구분 및 버전 표기는 `패치` 또는 `베타`로 간단히 표시한다(예: `v0.9a 패치`, `v0.5b 베타`). 기존 저작권·책임 고지 문구나 실제 파일명·다운로드 링크의 정확성은 훼손하지 않는다.
- 젤다 3개 상세 페이지의 콘텐츠 상단에 시리즈 간 바로가기 버튼(`series-link`)을 복원하지 않는다. 개별 페이지의 패치 다운로드와 공통 메뉴는 유지한다.
- 프로젝트 상세 페이지의 상단 브랜드 링크는 `<a class="brand" ...>HANMARU</a>` 단독 텍스트로 통일한다. `/ PATCH ARCHIVE`, `/ KOREAN PATCH ARCHIVE`, `/ ZELDA PATCH ARCHIVE` 같은 보조 문구를 다시 추가하지 않는다. 홈으로 가는 링크는 유지한다.
- 게임별 소개는 기존 `#game-spotlight` 앵커를 유지하되, `assets/css/game-catalogue.css`의 **레트로 게임 카탈로그 지면**으로 표시한다. 왼쪽에 게임 화면 **큰 사진 1장 + 작은 사진 2장**과 화면별 짧은 캡션, 오른쪽에 작품 고유의 시스템·분기·비하인드 요소를 짧게 해설한다. 상단에는 기종·연도·장르를 짧은 띠 형태로 기재한다. 책의 개별 사진이나 판면을 복제하지 말고 자료형 레이아웃이라는 편집 원칙만 참고한다. 게임을 모르는 방문자도 사진과 해설만으로 실제 플레이를 상상할 수 있게 쓴다. 기술적 한글화·버전·QA 수치로 시작하지 않고, 확인되지 않은 일화는 사실처럼 쓰지 않는다.
- 원작 스크린샷과 한국어 패치 적용 화면을 구분해 캡션을 표시하고, 외부 이미지에는 출처 링크를 적는다. 표지 이미지·원작과 다른 작품·실제 게임이 아닌 생성 이미지를 게임 화면으로 소개하지 않는다. 새 이미지 URL은 HTTP 응답과 MIME 유형을 확인하고 원본 종횡비를 유지한다. 스크린샷을 임의 확대·왜곡·AI 재생성하지 않는다. `href="#overview"`가 있다면 새 `#game-spotlight`와 일치시키고 중복 소개 섹션을 만들지 않는다. 스크린샷은 가능한 원본 게임의 서로 다른 장면을 고르되, 캡션은 실제 화면이 보여 주는 내용만 기술한다.

- 모든 프로젝트 페이지에는 `assets/css/floating-toc.css`와 `assets/js/floating-toc.js` 공통 목차를 연결한다. 데스크톱에서는 본문 오른쪽 고정, 좁은 화면에서는 펼칠 수 있는 목차 버튼으로 제공한다. 페이지에 존재하는 섹션을 자동 탐색하며 현재 위치 표시·맨 위로 이동·ESC 닫기를 지원한다.
- `assets/css/image-lightbox.css`와 `assets/js/image-lightbox.js`를 모든 프로젝트 페이지에 연결한다. 카탈로그 스크린샷·패키지·한국어화 이미지를 클릭하면 페이지 이탈 없이 확대 팝업으로 표시하고, 갤러리 좌우 이동·키보드 조작·ESC 닫기·배경 클릭 닫기를 지원한다. 원본 이미지 URL은 그대로 사용한다.
- 프로젝트별 아트 배경은 사용자가 승인한 공통 `assets/css/game-themes.css`에서만 관리한다. 각 페이지 <body>의 `class="game-theme" data-game-theme="작품별-ID"`와 `game-themes.css` 연결을 유지한다. 원작 일러스트·당시 전단지·패키지 아트 중 **확인된 작품별 자료**를 사용하고, 출처를 `theme-art-credit`에 표시한다.
- 게임별 배경과 포인트 컬러는 달라도 본문 구조·카탈로그 3장·패치 다운로드·해시·법적 고지·플로팅 목차·이미지 팝업은 공통으로 유지한다. 어두운 오버레이로 가독성을 보장하고 모바일에서는 이미지 장식을 낮춘다. 새 이미지는 HTTP·MIME·실제 작품 일치 여부를 확인한다.
- 문서 목적이 아닌 장문 회고, 01/02 장식 번호, CODEC 스타일, 공통 테마 파일을 벗어난 임의의 페이지별 CSS 분기, 미확인 QA 성공 문구 금지

## 제작 절차
1. 최신 원격 브랜치와 승인된 페르소나 HTML·슬레이어즈 HTML·표준 문서 확인
2. 게임 패치 빌드 보고서·CUE·Track 수·ZIP·해시·다운로드 링크와 실제 작업 내역 교차 검증
3. 페르소나 HTML을 복사해 **텍스트와 검증된 메타데이터만** 교체하고 공용 CSS를 그대로 사용
4. `python tools/verify_detail_template.py <게임-slug>` 실행. 비교 구조·공통 CSS·권리 고지·원본 비율·절대 링크·중복 ID·모바일 CSS·오류 문구 검사
5. 데스크톱 1440x900 / 모바일 390x844 Chrome 또는 Edge 스크린샷으로 페르소나·슬레이어즈·신규 페이지를 나란히 검수. **스크린샷 불가 시 시각 검수 완료를 주장하지 않는다**
6. 기존 다운로드 URL 및 해시 유지 여부를 확인하고 변경 파일만 커밋. 사용자가 푸시를 요청한 경우 검증 후 바로 push. 최종 답변은 수정 경로·커밋·검증 범위·공개 주소 포함
